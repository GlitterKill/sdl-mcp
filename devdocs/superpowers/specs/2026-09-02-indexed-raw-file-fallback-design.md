# Indexed Raw File Fallback Design

**Date:** 2026-09-02  
**Status:** Approved for implementation

## Problem

`file.read` rejects source-like extensions before checking whether SDL can
actually retrieve structured code. In SDLBench, indexed but unparseable `.mjs`
files therefore had no usable SDL retrieval path: skeleton retrieval failed,
source windows required unavailable symbol evidence, and raw reads were denied.
Agents retried retrieval instead of reading one bounded file segment.

Both `file.read` and `sdl.file { op: "read" }` already route through
`handleFileRead`. The fix belongs there, not in `runtimeExecute`.

## Decision

Permit a bounded raw read when the server determines that SDL cannot provide
structured retrieval for the requested file.

The caller cannot assert that a file is unparseable and no new override flag is
added.

## Authorization

For a source-like path, `handleFileRead` will make one server-side capability
decision against the current repository version:

1. If current structured retrieval is available for the file, reject the read
   and direct the caller to `sdl.context` or `sdl.retrieve`.
2. If no current structured representation is available, allow the existing
   raw-read path only when the request is explicitly bounded or targeted.
3. If the file is not present in the current index, treat it as non-indexed and
   allow the existing raw-read path.

Structured retrieval is available only when the current index has usable
parser-derived code data for that path. File extension alone is not evidence of
structured availability.

This is the policy gate: repository state and retrieval capability decide
access. Request data cannot override it.

## Bounds

The fallback reuses the existing `file.read` controls:

- Path containment and symlink revalidation.
- File-size, byte, and token hard limits.
- UTF-8-safe truncation.
- Existing range, search, and structured extraction behavior.

For source-like files without structured retrieval, the request must include at
least one explicit limiter or targeting operation, such as `maxTokens`,
`maxBytes`, `offset` plus `limit`, or `search`. An unbounded fallback request
is rejected with an actionable bounded retry.

The response will include a stable optional marker,
`retrievalFallback: "indexed-unparseable"`, only when a current indexed file is
served through this fallback. Non-indexed reads keep their existing shape.

## Workflow Instructions

Update the canonical workflow instructions to say:

> Use structured SDL retrieval for indexed source. When SDL reports that
> structured retrieval is unavailable, use a targeted, bounded
> `sdl.file { op: "read" }` fallback. Do not retry broad raw reads or use
> `runtimeExecute` to inspect files.

Synchronize:

- `templates/SDL.md`
- `templates/AGENTS.md.template`, `CLAUDE.md.template`, `CODEX.md.template`,
  `GEMINI.md.template`, and `OPENCODE.md.template`
- `templates/sdl-mcp-agent-workflow/SKILL.md`
- Generated root `SDL.md`, `AGENTS.md`, `CLAUDE.md`, `CODEX.md`, `GEMINI.md`,
  and `OPENCODE.md`
- Session-start and pre-tool-use guidance generated by
  `src/cli/commands/init.ts`
- The installed `sdl-mcp-agent-workflow` copy, after repository changes are
  verified

Generated files will be patched surgically. They will not be regenerated
wholesale because user-maintained sections may differ from templates.

## Tests

Add focused checks for:

1. Parseable indexed source remains denied.
2. Indexed source without structured retrieval accepts a bounded read.
3. The same file rejects an unbounded read with an actionable retry.
4. Caller input cannot force fallback for parseable source.
5. Existing path, symlink, size, byte, and token protections still apply.
6. `file.read` and `sdl.file { op: "read" }` have identical behavior.
7. Canonical and generated workflow text contains the fallback rule.
8. The optional response marker is schema-valid and deterministic.

Update golden/determinism fixtures only if the public response shape requires
it.

## Non-Goals

- No `runtimeExecute` behavior change.
- No general raw access to parseable indexed source.
- No new `codeNeedWindow` path mode.
- No caller-provided `unparseable` flag.
- No index refresh.
- No new configuration setting.
